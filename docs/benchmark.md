# Synthetic benchmark

Run a deterministic synthetic diagnostic:

    cabid benchmark --output results/synthetic-benchmark.json --seed 20261113 --per-class 50
    cabid benchmark --output results/b.json --format md   # also writes results/b.md

It generates benign regular activity, synthetic burst/self-parent/file-target
behavior anomalies, and incomplete telemetry, then compares three models:

| Model | Definition |
| --- | --- |
| `temporal_only` | single temporal threshold — the baseline |
| `cabid_core` | temporal + ancestry + lifecycle + completeness gate |
| `cabid_with_baseline` | the core plus novelty against a profile fitted from the generated benign splits |

A case is a positive detection when the verdict is anything other than
`NO_ANOMALY_DETECTED`; that rule is written into the report so numbers cannot be
read out of context. Per-scenario metrics are reported for both the wide and core
models (`scenario_metrics`, `scenario_metrics_core_only`).

Because the fixtures are generated, the baseline profile is synthetic too: it
demonstrates the plumbing and the expected direction of effect, not tuned values.
`--config` and `--baseline` let an experiment swap in real ones.

This is a software regression fixture, not a real-world effectiveness study.
Labels and scenarios are generated by code; they do not represent independent
hosts or real attack traffic. Do not cite these metrics as operational IDS
performance. A defensible study requires preregistered scenarios, independently
labelled data, splits by host/session/scenario family, and measured sensor coverage.
